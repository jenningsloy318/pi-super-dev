## [Unreleased]

### Added
- **Unified verification convergence loop.** The main pipeline now uses one Stage 10 verification state machine instead of separate review and integration loops: every attempt starts with fresh code-review + adversarial-review + deterministic build evidence, integration runs only after those pass, and any review/build/integration fix forces the next attempt to restart at review before testing again. Terminal success now requires review approval, build green, and integration passed (or explicit no API/UI surface) on the same final code state; max-attempt exhaustion stops before applying an unreviewed final fix. The run state records per-attempt local timestamps, durations, review/build/integration outcomes, failure signatures, code-state hashes, and fix-change evidence under `__verificationAttempts`. Integration tester side effects are guarded by the same hybrid boundary approach as RED tests: obvious test/runtime artifacts are allowed, ambiguous paths go through the LLM boundary classifier, and production-file writes stop the loop without routing the problem to the implementer. New focused tests cover review-fix-review-integration, integration-fix-review-integration, no final unreviewed fix, and tester production-write rejection.
- **Implementation symbol/hollow-file gate — kills the "silent-empty-success" failure mode.** A new `computeSymbolGate` (`src/build-runner/gates.ts`) is AND-ed into phase-green alongside buildGate/deliverableCheck/changeGate: a claimed source deliverable that EXISTS (so it passes the deliverable + change gates) but contains NO language symbols (doc-comment-only / empty shell) now FAILS the phase, with the hollow files fed into the next implementer retry. Catches the exact failure observed in run `2026-07-28T13-59-52` (Phase 3 shipped as ~1.5KB doc-comment-only shells while the summary claimed "3/3 complete", triggering a ~49min review-fix loop + a stagnation break). Language-aware symbol probes (rust/go/python/ts-js) over comment-stripped source; never throws and degrades to pass on unreadable files / unknown language / phases with no source files (never blocks infrastructure or doc/config-only phases). New: `tests/symbol-gate.test.ts` (9); stub added to the 2 explicit build-runner test mocks. `npm run typecheck` strict-clean; full vitest suite green (1527 tests).
- **HITL escalation: super-dev now ASKS the user (ctx.ui.select) when it hits an unrecoverable blocker, then continues based on their decision.** An escalate(failure) callback is threaded from extension.ts -> RunOptions -> StageContext and fired inline at gate exhaustion (nodes.ts) + verify-loop stagnation (verify.ts) BEFORE the abort. Interactive: ctx.ui.select with options (retry-with-guidance / accept-limitation / abandon) + ctx.ui.input for guidance. Retry: rollbackWorktreeTo + appendUserNotes -> stage re-runs with guidance. Headless: report + fail. Default-on in TUI/RPC. Never throws; bounded by ESCALATION_RETRY_CAP=2. typecheck clean; 1574 tests green.
- **Mid-run user context: type during a super_dev run and it's captured + persisted for every subsequent stage.** Free-text typed while the pipeline runs (in BOTH foreground and background modes — previously the background default discarded it) is now captured and appended to a durable `<specDir>/.user-notes.json` (mirrors `.knowledge.json`: cleared at pipeline start, kept on resume, never read by agents — the pipeline injects it). Each specialist's prompt gains a `## User context (added during the run)` block carrying all notes accumulated so far, so context added mid-run reaches every remaining stage. Slash-commands (`/super-dev-stop`, `/reload`, …) still pass through unchanged. Delivery is non-interrupting (picked up at the next agent boundary, like pi-subagents' file-backed steer queue). The fragile live-steer path (`session.steer` / `onSteer` / `makeSteer` / `SteerSink` / the `activeSteerForwarder` state + setter) is REMOVED — the durable file + between-agent drain is the sole delivery contract; `applyThinkingLevel` is intentionally kept. New: `src/render/user-notes.ts` + `tests/user-notes.test.ts`; rewritten `tests/workflow-user-steer.test.ts`; updated `tests/input-handler.test.ts`; removed the two live-steer test files. Independently reviewed (approved, no blockers/issues). `npm run typecheck` strict-clean; full vitest suite green (1518 tests).
- **Inherit model settings while isolating ambient agents/extensions via explicit role extensions + excludeTools (spec-17 follow-up).** Specialist `pi` agents now keep ambient discovery disabled by default in BOTH backends: subprocess uses `--no-skills --no-extensions --no-context-files --no-prompt-templates`, while the session backend uses `DefaultResourceLoader({ noExtensions: true, noSkills: true, noContextFiles: true, ... })` plus empty AGENTS.md/CLAUDE.md overrides. This keeps repo-bundled `agents/<name>.md` as the sole role definition and prevents installed packages such as `pi-subagents` from discovering `~/.pi/agent/agents` or project agents. Research/browser capabilities still work through explicit `-e` role extensions only (`pi-web-access`, `pi-mcp-adapter`, `pi-browser-cdp-extension`). Recursion remains blocked by `excludeTools: ["super_dev"]` / `--exclude-tools super_dev`, and subprocess agents now receive a generated `<control>` contract from `controlKeys` plus one corrective retry when the control block is missing or incomplete. `tests/pi-spawn.test.ts` pins the isolated argv and role-extension behavior.

### Fixed
- **Build gate now executes touched nested Node modules from their module directory.** The deterministic build gate still runs the root commands, but for Node workspaces with nested `package.json` files it also resolves touched module directories from git and runs their `build`, `test`, and `typecheck` scripts with `cwd` set to that module. Nested packages inherit the root workspace package manager when they do not declare their own, and run labels include the module path (for example `auth-service: pnpm run test`). Package-relative test failures such as `src/fail.test.ts` are matched against root-relative touched paths such as `auth-service/src/fail.test.ts`, preventing the npm in-scope classifier from incorrectly treating the module failure as out-of-scope.
- **Implementation RED oracle now plans and runs tests from the owning package directory.** The RED check first resolves and logs each test command as `{cwd, argv}` before spawning it, so nested package tests no longer fall through to a monorepo root script such as `pnpm -r run test` that can exit green without executing the target. Node `node:test` TypeScript files with package-local `tsx` run as `node --import tsx --test <relative-test>` from the package cwd, Node runner failure markers are classified as RED, and weak/polluted RED changes are restored before retry so stale generated tests cannot contaminate later attempts.
- **Stage traceability and merge gates are now source-backed.** Research reports must include real `http(s)` source URLs unless they explicitly disclose unavailable web/search tooling and mark claims unverified; the research prompt records the repository search-provider order (AnySearch, Firecrawl MCP/CLI, Tavily remote MCP, Tinyfish). The BDD gate now validates requirements-to-scenario traceability by requiring every `AC-NN` from the requirements doc to appear in the BDD doc with no dangling AC refs. The spec gate now requires BDD-to-spec scenario coverage, rejects unknown scenario refs, and verifies every task maps to a declared phase. The spec prompt also receives prototype report evidence and tells the spec writer to incorporate prototype verdicts, measurements, and adjustments. Merge is blocked unless Stage 10 integration verification explicitly passed, preventing a tolerant sequence from reaching merge after failed or skipped verification.
- **Inherit the main session's model WHOLESALE (spec-15 regression fix).** The spec-15 model-inheritance captured only `ctx.model?.id` (a BARE id) and re-resolved it via a fresh `ModelRuntime` full-catalog scan (`resolveSessionModel`/`splitModelRef`). That discarded the provider, so an inherited bare id like `glm-5.2` ambiguously matched a DIFFERENT provider's same-named model (or fell through to `findInitialModel`'s first-available), landing specialists on an unauthenticated provider (`opencode` → "No API key found") instead of the parent's real model (`custom-endpoint/glm-5.2`) — a live regression that blocked the pipeline. Fix adopts pi-subagents' inherit-wholesale pattern: `extension.execute()` now captures the FULL `ctx.model` object (requiring BOTH `id` AND `provider`, mirroring `normalizeParentModel`) and threads it as `inheritedModelObject` (replacing the bare-id `inheritedModel` string through `RunOptions` → `realAgent.common` → both backends). The session backend passes that object DIRECTLY to `createAgentSession({ model })` — no re-resolution, so the specialist runs on the parent's EXACT model (same provider/headers/baseUrl); the subprocess backend derives the parent's qualified `provider/id` for `--model`. The fragile `resolveSessionModel`/`splitModelRef`/cross-provider bare-id scan is DELETED; explicit overrides (`params.model`/`SUPER_DEV_MODEL`) now resolve PROVIDER-SCOPED only (`resolveExplicitSessionModel`: a qualified `provider/id` resolves within the named provider; a bare id falls through to the settings default) — mirroring pi-subagents' rule that a qualified query "never silently switches providers." Additive + no-throw; older/non-TUI ctx (no model) and an explicit override both degrade cleanly. Subsumes Gap #1 and practically closes Gap #2 (the custom-endpoint/glm-5.2 case resolves correctly). `npm run typecheck` strict-clean against the 0.82.1 type surface; full vitest suite green (1520 tests).

- **Git change-tracker with claimed-vs-actual cross-check gate (spec-11).** A new `src/tracking.ts` `ChangeTracker` brackets **every stage (start + end)** and **every implementation phase (start + end)** with a git snapshot (`rev-parse HEAD` + `status --porcelain` baseline; `diff --name-status <beginHead>` UNION `status --porcelain` delta), persisting an append-only `<specDir>/change-tracker.jsonl`. Each phase-end record carries a git-derived `gitActual {created, modified, deleted}`, the agent's claimed `{filesCreated, filesModified, filesDeleted}`, and a one-directional cross-check (`claimedNotChanged` vs `changedNotClaimed`). Never throws: git-unavailable → record + `changeGate.pass = true` (never block). Stage bracketing uses the minimal-touch `ctx.events` subscription seam; the per-run singleton (`activeTracker`/`setActiveTracker`) mirrors `activeRun` and is cleared in `execute()`'s `finally`. ## [0.3.0] - 2026-07-06

### Added
- **Workflow resume (memoized replay).** An interrupted `super_dev` run (crash, abort, timeout, closed terminal) can now resume from where it left off instead of re-running from scratch. Uses the durable-execution replay pattern (Temporal-style): every run captures its agent-call results to `<specDir>/.resume-cache.jsonl`; on resume (`super_dev({ resume: true })` or `resumeSpecId: "07-foo"`), the cache is loaded and `ctx.agent` memoizes — completed calls return their cached result, the first uncached call re-runs, and the workflow continues. Agent-call granularity (resumes mid-verify-loop / mid-phase) via a deterministic `callId#seq` key. The worktree is reused (it's git ground truth). A fully-successful run clears its cache + writes a `.complete` marker so it isn't re-resumed. Design + decisions in `docs/findings/workflow-resume-deep-research.md`.

## [0.2.0] - 2026-07-06

**Trustworthy convergence, safety, and UX.** This release closes the highest-leverage gaps from the rewrite review (`docs/findings/rewrite-review-vs-super-dev-plugin.md`): the verify-loop's convergence signal is now real (not self-reported), spawned specialists are guarded against catastrophic commands, stuck loops break early, language-specific guardrails are richer, and long runs get a live phase-tracker. Verified against the Pi SDK in `docs/findings/pi-sdk-architecture-verification.md` (C1–C15).

### Added
- **Deterministic build/test/typecheck gate (Gap A).** New `src/build-runner.ts` actually runs the project's build/test/typecheck commands (cargo/go/pytest/npm+pm with bun/deno detection) with bounded 120s timeouts, replacing trust in the QA agent's self-reported `buildSuccess`/`allTestsPass` (vacuous-pass risk). Wired into three gate points: per-phase in `implementation.ts` (the hard oracle that feeds real errors back into retries), a pre-merge gate in `stages/index.ts` (skips merge when code fails to build), and inside the verify-loop in `verify.ts` (gives non-service apps a real convergence signal alongside the merged review verdict). Non-fatal for greenfield repos (no manifest → no commands → pass). The redundant per-phase QA self-report spawn was removed.
- **Safety guardrails for spawned specialists (Gap 4.3).** New `src/safety.ts` ports the original plugin's `block-dangerous` + `protect-files` hooks as a Pi-native inline `tool_call` ExtensionFactory (hard, uniform interception of every tool the child calls). The session backend now creates each child with a `DefaultResourceLoader({ noExtensions: true, extensionFactories: [safetyFactory] })` — `noExtensions:true` suppresses ambient global-extension discovery (inline factories still load, verified), so children are both guarded AND deterministic. Protected-file logic blocks OVERWRITES of existing secrets only (creates + `.env.example` allowed). The subprocess backend gets a soft `safetyPreamble()` prepended to its system prompt (defense-in-depth).
- **Verify-loop stagnation detection (Gap 4.6).** The verify-loop now tracks the merged review-findings signature (`file|severity|title`, sorted → order-independent, ignores reworded `detail`) across iterations and breaks early (non-fatal, logged) when the SAME non-empty findings recur on two consecutive rounds — instead of burning all 4 iterations re-fixing the same thing. Exact-set equality (v1).
- **Per-language specialist profiles (Gap 4.1).** Replaced the one-line inline `LANG_INSTRUCTIONS` with prose profiles under `agents/lang/{rust,go,python,frontend,backend}.md` (commands, coverage threshold, mandatory test file-organization rule, top idioms — current 2024-2026 stacks, distilled from the original plugin's dedicated agents; no code samples to save tokens). `route-specialist` loads the matching profile and it is now injected into BOTH the implementer and the tdd-guide prompts, so a single generic implementer gets language-specific guardrails. Mobile/desktop specialists deferred until `detectLanguage` learns those stacks.
- **Protocol reference docs (Gap 4.4).** Added `docs/reference/{verification-gates,iteration-loops,pivot-protocol}.md`, adapted from the original plugin's reference: stripped plugin-specific machinery (team-lead/doc-validator/`AskUserQuestion`/`gate-build.sh`/spec-29 postmortem) and mapped each onto pi-super-dev's actual implementation (deterministic helpers, the `gate()` node with feedback-driven retries, `runBuildGate`, the verify-loop, stagnation detection). Each doc carries an honest header distinguishing design intent from current implementation (notably: full pivot protocol is deferred — only stagnation detection + planned escalation are wired).
- **Stagnation escalation UI (Gap 4.6′-lite).** When the verify-loop breaks on stagnation, the run now surfaces it two ways: an always-on `stagnation-report.md` in the spec dir + a diagnostic line in the run summary (baseline, all modes, non-blocking). Opt-in interactive mode (`escalation: "interactive"` in `~/.pi/agent/super-dev/config.json`, TUI/RPC only via `ctx.hasUI`) prompts a 3-option `ctx.ui.select` (revise spec / accept as known limitations / abandon worktree). Headless runs always fall back to the informative baseline. The `escalation` field defaults to `"informative"`. Full pivot/replay remains deferred (Tier-3); in Tier-2 the "revise" choice only surfaces the recommendation.
- **Workflow dashboard v1 (Gap Dashboard).** An always-on phase-tracker widget (`ctx.ui.setWidget`) renders live stage progression in TUI mode (`super-dev · M/N stages` + a ✔/●/⚠/↷ line per stage). `task()` nodes now emit structured `stage` events (running → terminal) on the existing event bus, piped through a new optional `ProgressSink.stage` callback — the same channel v2 will use for per-agent timing/token in a full two-panel interactive component. Headless (`print`/`json`/`rpc`) is a no-op; the widget clears at run end. v2 (two-panel `ctx.ui.custom()` with stop/pause/save keybindings) is deferred.
