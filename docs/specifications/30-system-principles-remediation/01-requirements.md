# Requirements — Fault-Classified Actuation, Signature Normalization, and Reused-Worktree Isolation (PRA–PRD)

**Date:** 2026-08-18  **Type:** fix  **Priority:** high

## Executive Summary

Run `2026-08-18T01-02-50-093Z` burned 4h39m and was cancelled at phase 1/4 because Stage 9 is an open-loop retry controller with one actuator (re-spawn implementer) driving against all fault classes, on an unpinned shared worktree carrying prior runs' out-of-scope dirt, with unarbitrated evidence — the gate's correct "regression — out-of-scope subjects PASS at clean merge-base 45b865ef" verdict had no actuator, so attempts 2–12 re-proved the identical pre-existing `internal/services/snow` failure while the no-progress detector stayed blind (volatile noise hashed 11 identical failures differently) and the judge only fired at attempt 14 after user cancel. This cycle fixes that one structural defect with four principle-derived fixes: **PRA** (deterministic fault classification before actuator selection, with quarantine+re-gate and first-occurrence judge routing for environmental blockers), **PRB** (normalized failure signatures so identical failures actually match and anti-windup engages), **PRC** (reuse hygiene — foreign uncommitted state detected and recoverably quarantined at setup, kill-switched), and **PRD** (a per-track environment-fault ledger consumed by later runs). All four are grounded in the 14 rules of `00-principles-and-rules.md`; all quarantine is stash-based, recorded, and reversible; no gate verdict may be resolved by editing out-of-scope code.

## Acceptance Criteria

**AC-01** — PRA (R-S2, R-S3): on any build-gate failure in the attempt loop (src/stages/implementation.ts), a deterministic pure classifier — no LLM in the classification floor — runs BEFORE actuator selection, consuming `BuildGateResult` (`outOfScopeErrors`, `inScopePass`, `baselineCheck?.status`) plus the own-scope evidence booleans (deliverable-check, change-gate, symbol-gate, tdd-oracle clean), and returns a fault class ∈ {`environmental-blocker`, `product-defect`, `unclassified`} with its legal actuator; the synthetic `[baseline-verify] …` block that the regression strip appends to `gate.errors` (gates.ts ~:546) is NOT a product failure and is excluded from the failure tally; genuine in-scope/mixed failures and absent-`baselineCheck` cases classify as `product-defect`/`unclassified` and keep today's retry semantics unchanged.

**AC-02** — PRA (R-S1, R-N1, R-S4): when every failure is out-of-scope (`outOfScopeErrors.length > 0`, and every `gate.errors` entry is either an `outOfScopeErrors` member or the excluded synthetic `[baseline-verify]` block per AC-01) AND `baselineCheck.status === 'regression'` AND own-scope evidence is green, the loop MUST NOT re-spawn the implementer for that cause on any attempt — testable in the `implementation.test.ts` style (stubbed `runBuildGate` seeded with a regression verdict over out-of-scope-only errors) by asserting the implementer agent's call count does not increase across blocker handling.

**AC-03** — PRA (R-N3, R-N5, R-N6): in the environmental-blocker branch, (a) if the dirt inventory is non-empty — canonical inventory rule, pinned once here and inherited everywhere: the current-attempt exclusion set is the implementer's CLAIMED files (`filesCreated`/`filesModified`) UNION the phase's declared scope; `gitActual` entries OUTSIDE that exclusion set are RC12c-class dirt and ARE quarantineable; tracked modifications or untracked files outside the spec-dir prefix, harness bookkeeping, and copied env files are likewise inventory members — the loop performs a recoverable quarantine — scoped `git stash push -u -- <paths>` with a ledger record — and then EXACTLY ONE gate re-run; the re-run MUST NOT inherit a baseline verdict memoized against the pre-quarantine worktree (the baseline.ts per-signature memo is invalidated/bypassed for the re-run); if the re-run passes or grants an evidence-backed `inScopePass`, the phase proceeds green through the existing `(gate.pass || gate.inScopePass)` branch with no further spawns.

**AC-04** — PRA (R-N1, R-S4): when there is no dirt, or the single post-quarantine re-run is still environmentally blocked, the loop routes to `runJudge` at FIRST occurrence (scope `stage9.impl-env-blocker.<phaseId>`) with BOTH evidence packets — the gate failure tail plus `baselineCheck` status/evidence plus the dirt inventory — offering `allowedRoutes: ["fix-environment"]` — the route already exists in `JUDGE_ROUTES` (judge.ts:37) and is already offered at `stage9.red-no-progress` (implementation.ts:1298, consumed as a RED-loop repair hint); this cycle adds its SECOND offer at the GREEN-phase env-blocker boundary (escalate-now always implied; an unoffered/unverified route degrades to escalate per existing judge behavior), never a second identical implementer spawn.

**AC-05** — PRA (R-N2): the environmental-blocker branch emits a log line that names the fault class and the next action, e.g. `Implementation <phaseId> environmental-blocker: out-of-scope-only failures, baseline=regression, own-scope evidence green — class=environment; next=<quarantine+re-gate>` or `… next=<judge: fix-environment/escalate>`, asserted by substring in stage tests.

**AC-06** — PRB (R-S5): `normalizeSignatureText` strips volatile noise — ISO-8601 timestamps (with/without timezone, with/without fractional seconds), UUIDs, durations matching `\d+(\.\d+)?(ms|s)\b`, and `(cached)` / `[cached]` markers — stripping applied BEFORE the existing whitespace-collapse/trim/800-char cap, so noise never displaces discriminating content past the cap.

**AC-07** — PRB (R-S5, R-S6): replaying the 11 identical snow failure texts from run 01-02-50 through `failureSignature` yields ONE identical `ProgressSignature.failure` across all attempts — the test uses in-repo fixture texts (verbatim excerpts with provenance noted, or replicas that cover every AC-06 noise class) and pins BOTH `ProgressSignature` components (`failure` AND `footprint`) constant across the replayed attempts; the second occurrence trips the existing `repeatedNoProgress` → judge/HITL escalation path, and no third identical implementer spawn occurs absent an explicit judge/HITL continue decision.

**AC-08** — PRB (R-S5, back-compat): signatures that differ only in stripped noise MUST compare equal; signatures differing in failing package/path (e.g. `internal/services/snow` vs `internal/services/auth`) or error class MUST NOT compare equal — no over-normalization, pinned by unit tests on both directions.

**AC-09** — PRC (R-N4, R-N5, R-N6): on entering a reused track (`reusedTrack === true`) or a resumed track (`options.resumeSpecIdentifier` set), `runSetup` (src/setup.ts) detects foreign uncommitted state in `worktreePath` — tracked modifications plus untracked files, excluding the spec-dir prefix, harness bookkeeping, and `copiedEnvFiles` — and quarantines it recoverably via scoped `git stash push -u` with a ledger record; absent the kill-switch, after setup the worktree contains no foreign tracked modifications (assertable via `git status --porcelain` in a temp-repo test).

**AC-10** — PRC (R-N2, R-N6): the setup quarantine emits a prominent log naming the quarantined paths, the stash ref, the recovery command (`git stash pop`), and the kill-switch name (`SUPER_DEV_NO_DIRTY_QUARANTINE=1`), following the existing `SUPER_DEV_NO_SPEC_REUSE` logging style in src/stages/setup.ts.

**AC-11** — PRC (R-N5): kill-switch `SUPER_DEV_NO_DIRTY_QUARANTINE=1` disables every automatic quarantine — both the setup-time quarantine (AC-09) and the in-loop quarantine (AC-03a) — leaving the worktree untouched with a detection-warning log only, matching the existing `SUPER_DEV_NO_BOOTSTRAP` / `SUPER_DEV_NO_SPEC_REUSE` convention.

**AC-12** — PRD (R-N7): quarantines and judge-environmental verdicts append one JSON line per event to `<specDir>/.environment-faults.jsonl` with exactly the keys `{kind, paths, stashRef, reason}` (`kind` ∈ {"quarantine", "judge-environmental"}; `paths`/`stashRef` may be empty/null for verdict records), mirroring the `.resume-cache.jsonl` in-spec-dir precedent; when the file exists, setup logs the prior-fault count for the track, and when absent emits no line; appends never throw.

**AC-13** — Safety (R-N6, R-N3): quarantine is never destructive — stash-based only (no `checkout`/`reset`/`clean`), its pathspec never includes in-scope or excluded files, it never runs when the kill-switch is set, and any failure of the quarantine mechanism itself (git error, unwritable ledger) degrades to a warning log plus the judge route in-loop / plain proceed at setup — never fatal, never un-throwing-contract-violating.

**AC-14** — Process: all changes are RED-first tested (each new behavior's tests fail on the pre-fix tree), `tsc --noEmit` exits clean, and the full vitest suite is green.
