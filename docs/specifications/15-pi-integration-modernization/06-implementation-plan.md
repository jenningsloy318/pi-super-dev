## Phase 1: Phase 1 — Inherit main-session model + thinking level (Feature 1; AC-01..05; SCENARIO-001..008)

The highest-leverage, core change. Thread additive `inheritedModel?: string` / `inheritedThinking?: ThinkingLevel` DEFAULTS through the full specialist-execution chain (extension.execute → RunOptions → realAgent.common → SpawnAgentOptions/SessionAgentOptions) so every spawned specialist on BOTH backends uses the live session's model and a thinking level no LOWER than the role default when no explicit param/env override is supplied. Widen `resolveThinking` precedence (per-call → SUPER_DEV_THINKING → INHERITED → role default) and add model precedence (explicit → SUPER_DEV_MODEL env [NEW] → inherited ctx.model.id → SDK/settings default), keeping `--model` pushed only when a model resolves. Pass `model`/`thinkingLevel` as `createAgentSession` options alongside the retained best-effort `applyThinkingLevel`, guarded against double-application. Capture `ctx.model?.id`/`ctx.thinkingLevel` defensively (never throw on older/non-TUI ctx). Touches src/extension.ts, src/types.ts, src/workflow.ts, src/pi-spawn.ts, src/session-agent.ts. Because this phase edits files shared by Phases 2 and 3 (session-agent.ts and extension.ts), it MUST land first; it is the prerequisite for the rest of the DAG.
## Phase 2: Phase 2 — Constrained tool sampling for structured_output (Feature 2; AC-06,07,08; SCENARIO-009..013)

Localized to src/session-agent.ts. Add an `isStrictCapable(schema)` helper (true ONLY for a typebox Object with ≥1 required non-Optional key and additionalProperties === false) co-located with `controlSchema`. Provide a strict-capable schema variant (`Type.Object({ …required typed keys… }, { additionalProperties: false })`) for stages with well-defined keys. In `structuredOutputTool`, set `constrainedSampling: { type: "json_schema", strict: "prefer" }` on the `ToolDefinition` ONLY when `isStrictCapable` holds — typed against the 0.82.1 `ToolDefinition.constrainedSampling` field. Never attach it to the current permissive controlSchema (all-Optional + additionalProperties:true) or any open/unknown-key schema; keep that shape ONLY as the fallback. PRESERVE `missingKeys()` + the single corrective re-prompt turn byte-identical as the non-capable-provider/permissive-schema fallback. Independent of Phase 1 functionally but edits session-agent.ts, so it runs AFTER Phase 1 lands (parallelizable with Phases 3 and 4 — distinct files).

## Phase 4: Phase 4 — Tag build runs with pi's bash session env vars (Feature 4; AC-10; SCENARIO-016,017)

Localized to src/build-runner/gates.ts (runBuildGate / BuildGateResult). Defensively read `process.env.PI_SESSION_ID` and `process.env.PI_MODEL`; when present, include them as a plain-ASCII correlation tag in the captured build-run metadata (e.g. a `# pi-session=<id> model=<model>` header line in the captured build log and/or an additive `correlation?: { sessionId?: string; model?: string }` field on `BuildGateResult`). No-throw when the env vars are absent; the captured build run is byte-identical to today when they are absent. Observability-only: do NOT change gate pass/fail logic, command construction, or timeout behavior; no ANSI/control codes in any mode. Edits a file untouched by other phases, so fully parallelizable with Phases 2 and 3 after Phase 1 lands.
