## Summary

Every AC is implemented by the smallest change at its named site, matching the ACTUAL code shapes (all signatures/line refs below were read from source, not the dossier paraphrase). Design highlights:

- **Approval chain (Phase 1):** `normalizeReviewVerdict`'s `PASS` branch gains the same guard as the approve family; a shared `NEGATED_APPROVAL_RE` guards both verdict classifiers; `reviewFindingBlocks` lets explicit `blocking === true` / high-class severity outrank prose status inference; the convergence-duty shield matches restatements by convergence fingerprint; the ledger merge preserves max severity class and blocking.
- **Secrets & worktree (Phase 2):** the cleanup blocklist predicate is DERIVED from `isEnvFile` (exported); copied env paths are appended to the git COMMON exclude file; worktree-add failure is fail-closed (prune + retry + throw with stderr); `commitWorktreeChanges` refuses `git add -A` in a main checkout without an explicit opt-in.
- **Track/resume state (Phase 3):** the referenced-spec branch sets `reusedTrack = true`; a fresh entry into an existing track truncates `.resume-cache.jsonl`; `STAGE_CALL_PREFIXES` covers debug/assessment/prototype (+ a deliberate `classify: []` per D2) with a source-grep drift-guard tripwire; judge/replan-lead rows are invalidated on every replan; non-routable deferred findings persist as `ownerStage: "human"` rows; a `.run-lock` (wx + live-pid check + stale steal) serializes same-track runs.
- **Doc validators & render (Phase 4):** `normalizePhases` round-trips fields; CommonMark fence pairing (same char, ≥ length, heading-implicit close) in `stripNonNormativeSections`; the non-normative heading vocabulary widens to H1–H4 + word-led qualifiers (pin flip per OQ-2); `phaseTestDeliverableErrors` is wired into `gate-spec-trace`; `gate-bdd` reads stripped content; render schemas pin `^AC-\d{2,}$`; the BDD Coverage Summary computes real numbers or is omitted; `readSpecDoc` accepts only spec-dir-contained paths.
- **Implementation loop (Phase 5):** `gitSpawn` forces `core.quotepath=false` and the separator regex becomes single-backslash; gitignored-but-present claims downgrade to an `ignoredVerified` advisory; the python RED oracle classifies usage/collection errors as `broken`; `repeatedNoProgress` matches ANY history entry; `expectedScenariosForPhase` merges `task.scenarioRefs`.
- **Process & prompts (Phase 6):** `runPi` decodes UTF-8 stream-exactly, parses the residual final line, and escalates SIGTERM→SIGKILL with a bounded settle; service teardown group-SIGKILLs and readiness polling is abortable; convergence round accounting clamps the +4 extension to the 3× ceiling and arms only on FRESH review readings; `execute()` refuses a second in-flight run and captures the run dir once; user notes are byte-capped head+tail at persist; every prompt builder fences untrusted text behind a length-escalating DATA fence with a standing preamble.
- **Fix-in-pass dispositions (Phase 7)** land with pinning tests per NFR-6; the release commit bumps 0.1.99 → 0.1.100 with changelog `### Fixed` bullets (NFR-4).

### Drift resolutions (design follows ACTUAL code; premise noted)

1. **ISS-01 / AC-08 — exclude file location.** The requirements and SCENARIO-017 name `git -C <worktree> rev-parse --git-path info.exclude`; the research empirically proved that path resolves to the worktree-private `.git/worktrees/<id>/info/exclude`, which **git never reads** (no per-worktree exclude source exists — gitrepository-layout(5), verified with `check-ignore -v` on git 2.47.3). **Design writes to `$(git -C <worktree> rev-parse --git-common-dir)/info/exclude`** (shared by the main checkout and all linked worktrees; append is idempotent, patterns are repo-relative and intentionally apply to every worktree). The scenario's observable assertions (path untracked, never staged/committed, `git check-ignore` exit 0) all hold under this mechanism.
2. **ISS-02 / AC-22 — pytest exit codes.** Exit code 4 is *usage/CLI error* (covers `ERROR: file or directory not found`); "no tests collected" is exit code **5**. Both classify `broken`. Per D3, implemented via **markers only** — `classifyRedStatus(language, combined, ok, ctx?)` keeps its signature (the boolean `ok` already encodes exit≠0); no test-fixture ripple.

```ts
/** M22/R-01: the convergence fingerprint — the SAME ownerStage+sourceGate+
 *  title+detail inputs the ledger records, hashed identically to the ledger's
 *  historical stableHash so pre-record enforcement can match restatements. */
export function reviewFindingFingerprint(ownerStage: string, sourceGate: string | undefined, title: string, detail: string): string {
	let hash = 5381;
	const input = [ownerStage, sourceGate ?? "", title, detail].join("\n").toLowerCase();
	for (let i = 0; i < input.length; i++) hash = ((hash << 5) + hash) ^ input.charCodeAt(i);
	return (hash >>> 0).toString(36).padStart(7, "0");
}
```
