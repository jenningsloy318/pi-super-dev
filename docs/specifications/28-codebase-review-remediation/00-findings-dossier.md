### M2: Subprocess stdout decoded per-chunk — multi-byte UTF-8 corrupted across chunk boundaries
Severity: medium. Sources: code-A:SD-02, adv-A:A-06

**code-A/SD-02** (confidence 0.85):
Detail: runPi accumulates `lineBuf += c.toString("utf8")` per 'data' event (src/pi-spawn.ts:492-493). When a stdout chunk ends inside a multi-byte codepoint (CJK, emoji, typographic quotes — routine in agent text that quotes source or writes non-English docs), toString('utf8') emits U+FFFD for the partial sequence and the next chunk's continuation bytes emit another. Verified experimentally: the outer NDJSON line still parses (U+FFFD is valid inside JSON strings), so the corruption is SILENT — the captured assistant text (lastAssistantText) and any <control> block embedded in it are mangled. Consequences: (a) extractControl's inner JSON.parse of the control block fails when the straddle lands inside it → control=null → corrective retry or 'produced no output' rejection; (b) when the straddle lands outside the control block, string values can carry U+FFFD into control values → rendered spec/docs artifacts contain replacement characters. Affects the subprocess backend, which is forced for browser agents (ui-tester/qa-agent), web-research agents, and SUPER_DEV_BACKEND=subprocess users. The existing tests (tests/pi-spawn-control-retry.test.ts) emit one pre-formed Buffer per run, so chunk splitting is never exercised.
Recommendation: Call `child.stdout.setEncoding("utf8")` (and same for stderr) immediately after spawn — the stream's internal StringDecoder buffers partial codepoints across chunks. Add a test that emits a JSONL line split mid-codepoint across two 'data' events and asserts the reconstructed line and extracted control are byte-identical.

**adv-A/A-06** (confidence 0.8):
Detail: src/pi-spawn.ts:493 does `lineBuf += c.toString('utf8')` per 64KiB chunk — a multi-byte UTF-8 sequence split across a chunk boundary decodes to U+FFFD in the reassembled line (corruption lands inside JSON string values, so JSON.parse usually still succeeds with mangled text — e.g. a non-ASCII filename or quoted prose in the control block).
