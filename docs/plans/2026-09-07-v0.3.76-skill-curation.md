## Problem (measured)

Ambient skill discovery injects ALL discovered skills (~297 cards ≈ **36.8K
tokens**) into EVERY delegated child's system prompt, used or not. Evidence
from run 2026-09-07T00-49-33-204Z (46 subagent calls, 11h, 99 agents):

- **1/99 actual skill usage** (research-agent → firecrawl): relevant skills DO
  get used when visible — the defect is the other 290+ cards burying them.
- **≥1.69M tokens cumulative ≈ half of all uncached input** was the fixed
  listing — pure attention dilution (Anthropic context-rot) plus cost.
- Smoking gun: task-classifier completed a 127-output-token classification on
  **50,914 input tokens**.

v0.3.75's usage-report "fixed floor" line is the before/after yardstick.

`skill: ["a","b"]` → curated cards only · absent → today's ambient ~37K.

## Design

- **Engine-side resolution** `skillsForCall(role, config)` in
  `src/agents/agent-runtime.ts` (beside extensionsForAgent):
  - config `agentSkills: Record<role, false | string[]>` (mirrors agentModels)
  - mechanical classifier roles (task-classifier, judge, tdd-coverage-classifier,
    red-boundary-classifier, file-classify) default `false` — they never read
    skill cards
  - research/web roles default to a curated research set (firecrawl + the
    repo-declared research stack)
  - every other role defaults **absent (ambient)** — fail-open; the user's
    standing decision "subagents should be able to use pi skills/extensions
    when needed/matched" is preserved for non-classifier roles
- **Threading**: `DelegationAgentOptions.skill` → request `skill` field in
  delegation-backend (one-line wire change, zero upstream changes needed).
- **Escape hatch**: `SUPER_DEV_SKILLS=ambient` restores today's behavior for
  all roles (opt-OUT of curation, not a forgotten opt-IN — Option-C doctrine
  from v0.3.70).
- **Measurement**: next real run's usage-report fixed-floor line vs this
  run's ≈37K floor is the acceptance signal; target ≥50% floor cut with zero
  lost skill-usage events on research roles.

## E2E verification (2026-09-07, closed the open item — AND refuted the parent-seam reading)

First probe run (scratch pi + pi-subagents 0.66.0, repo-registered agents):
per-call `skill:false` did **NOT** suppress the child-side ambient listing —
both probes reported the identical full ambient inventory. Root cause
(source, child-launch.ts:298): `noSkills: !input.inheritSkills` — the
child's ambient discovery is gated by the REGISTRATION-level inheritSkills
flag; the per-call request `skill` field only adds a parent-built curated
injection block (execution.ts:1782-1785 buildSkillInjection). With sd-*
registered inheritSkills:true, ambient is always present.

**Corrected architecture (implemented + verified):**
- curated roles (classifiers + research) register `inheritSkills:false`
  (register-agents.ts: skillsEnabled() && (ambientSkillsForced() ||
  !curatedSkillsRole(name))) — this is the ONLY switch that suppresses
  child ambient;
- curated cards arrive via the per-call request `skill` array
  (skillsForCall → delegation-backend → request.skill → injection);
- capability roles stay inheritSkills:true (ambient, untouched).

Second probe run (zai/glm-5.3), three-way discrimination:
| probe | config | child answer |
|---|---|---|
| 1 | classifier inheritSkills:false, no skill field | **NONE** |
| 2 | research-agent inheritSkills:false + skill:["firecrawl"] | **firecrawl** |
| 3 | implementer inheritSkills:true (control) | full ambient listing |

## 11. Source-material alignment (docs/requirements/sdlc/tip.md, added 2026-09-07)

The user's two-point tip maps directly onto this wave:

1. **Tests vs evals** — tests verify deterministic seams (our 3353-test suite:
   skillsForCall tiers, wire fields, collector dedupe); evals verify
   NON-deterministic agent behavior (did the child pick the right tools,
   follow the right trajectory). Our incident-regression eval harness
   (v0.3.69 E4, `npm run evals`) is still code-checked, not LM-judged; the
   L2 tool-usage.jsonl telemetry landed here is exactly the substrate a
   future trajectory-eval needs (labelled runs: which roles actually used
   which curated cards). Logged as the natural next E-wave step, not new
   v0.3.76 scope.
2. **Six context types** (Instructions / Knowledge / Memory / Examples /
   Tools / Guardrails) — ambient skill injection conflates Knowledge+Examples
   (149 cards, ~37K tokens) with noise; curation is precisely the discipline
   of admitting only the Knowledge/Examples slices the role's Instructions
   call for. The L1 domain catalog + per-request curated arrays are the
   mechanical form of that selection.
