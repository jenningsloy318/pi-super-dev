## §2 The five root-cause defects

**C1 — Poisoned-baseline forward-continue** (`src/stages/implementation.ts:3885-3887`)
When a phase ends partial the engine logs `partial after N attempt(s) — continuing to the next phase` **even when the full-suite gate is red on tests outside the phase's declared targets** (baseline-verify itself prints "NEW on this branch"). Phase 1's unfinished census work made `npm run test` permanently red; every later phase inherits an unwinnable gate. 12 phases × 30-45min/attempt = the 24h. The harness *knew* the failures were out-of-scope but had no rule connecting that knowledge to phase-advance.

**C2 — Judge evidence shape drift: judge routing subsystem dead since v0.3.70** (`src/render/schemas.ts:36` vs `src/stages/judge.ts:205,211-214`)
The TypeBox schema (v0.3.70, 2026-09-05) declares `evidence: Type.Array(Type.String())`; the verifier reads `ev.file` / `ev.quote` — object shape. Every schema-valid judge verdict **fails** verification → corrective re-call (3-4 min + $) → still fails → "escalating with the diagnosis preserved" → **route discarded**. This run: 6 judge calls, 0 accepted, 3 correct `replan-upstream` diagnoses thrown away. 22 versions of escape-valve engineering, multiplied by zero.

**C3 — RED-phase test weakening is legal** (observed phase-1 21:55)
The "agent must not weaken the check on its own work" invariant exists only during GREEN. During RED authoring the tdd-guide may edit any pre-existing test file — it responded to "unsatisfiable RED" by gutting 3 guard suites, making the oracle green and misrouting phase 1.

**C4 — Test-edit ban deadlock with no reachable exit** (`tdd-tests-modified-during-green ... RESTORED from confirmed RED`)
The repo's own census tests *require* atomic amendment ("every census mirror amended in the same atomic change"), but the boundary forbids editing those test files during GREEN. The error honestly says "fold it into the declared scope (requires a spec change)" — **but no mechanism performs that spec change mid-run**. Phases 4-6 were structurally impossible and the loop said so for ~6 hours.

**C5 — Unbounded attempts + exact-signature no-progress** (`src/stages/implementation.ts:1922`, `:125-134`; `repeatedNoProgress` matches ANY prior history entry, not consecutive-only)
The attempt loop's only bound is `ctx.budget.check()` (global spawn budget). **No wall-clock fuse, no per-phase attempt cap.** The no-progress valve requires an *exact* `(failure, footprint)` repeat; varying implementer approaches changed the footprint, so phases ran 5, 7, 9, 11 attempts. Budget died at hour 24.

## §3 "Is the static rule too narrow?"

Yes, but that is 1/5 of the answer:
1. The v0.3.79 static plan-feasibility validator is too narrow — it checks cross-phase identifier/contract contradictions and emits plan-internal `shared-file-coupling` **advisories** (non-blocking), but not **repo-side file-ownership coupling** ("phase N's completion requires editing test files that phase M's frozen invariants pin" — the census class lives in repo test semantics, outside the plan). The judge diagnosed exactly this; we discarded it (C2). No static rule can fully catch this class — the coupling lives in repo test semantics — which is why the *dynamic* escape (replan) matters more than a wider static rule.
2. The bigger killers were not static rules at all: C1 (a policy: partial→continue), C2 (a wiring bug that killed the dynamic escape), C5 (a missing bound). We sharpened static knives while the sword was broken.

> We verify each fix against the *last observed failure* (incident regression test) instead of verifying the *system's invariants* (cross-module contracts, end-to-end behavior, failure-path liveness). Each fix is locally validated, globally unverified.

Our own methodology P6 says "cross-module contracts get dynamic cross-check tests". ## §8 New principles (constitution amendments)

1. **Invariant-first, not incident-first.** Before fixing an instance, name the invariant violated and fix at the invariant's scope. An incident fix without an invariant is a hole patched, not a fence mended.
2. **Bounded failure is the definition of working.** Flawless for an LLM-driven system ≠ never fails; it = every failure detected early, bounded in cost/time, routed to a decision. (Antifragility: each incident makes the *class* impossible, not the instance.)
3. **No subsystem may die silently.** Every cross-module contract has (a) one shared definition, (b) a CI cross-check generating from the definition into the real consumer, (c) a health counter in run-metrics.
4. **Stop-the-line on poisoned baselines.** Red state never propagates forward; the Andon cord beats best-effort continuation.
5. **Rules have doors.** Every mechanical block offers a reachable, mechanical approval route — or it isn't shipped.
6. **Verify the system, not the fix.** E2E golden path in CI; every wave answers "what could this break?" with a test.
7. **Simplicity budget.** Complexity is debt; each wave removes or merges something on the way in.

## §12 Grill layer — closing the requirements/spec definition gap

**The gap**: spec-25/26 both failed on requirements that were never interrogated against the REPO: cross-phase file coupling (census lockstep), closed-set invariants, ownership — all decidable at spec time by reading the code. Our requirements-clarifier asks about INTENT; nothing walks the repo-fact decision tree.

**Method source** (Superpowers `grilling`/`grill-me`/`grill-with-docs` + `domain-modeling`, extracted 2026-09-10):
- Interview relentlessly, **one question at a time, ALWAYS with a recommended answer**; walk the decision tree branch-by-branch resolving dependencies one-by-one.
- **Facts from the code are looked up, never asked; decisions are put to the human** (or auto-accepted with the recommendation under config when confidence is high).
- Stop condition = **shared understanding**: every decision-tree branch resolved; do not enact the plan until confirmed.
- grill-with-docs artifacts: **CONTEXT.md-style glossary** (ubiquitous language — the exact terms whose ambiguity hurt us: "census", "registry", "backend") + **ADRs only for hard-to-reverse + surprising + real-trade-off decisions** ("closed 17-name union" was ADR-grade and never recorded as one).
- domain-modeling discipline: challenge terms against the glossary; sharpen fuzzy language; stress-test with concrete edge scenarios; cross-reference code claims against actual code; write decisions down the moment they crystallize.

**Design — Stage 0.5 `grill` in super-dev:**
1. **Deterministic repo-fact pre-flight** (zero-LLM; first home = extension of plan-feasibility.ts, moves to `src/stages/grill-facts.ts` with §11): for every file path the plan declares — existence, owning invariants (grep census/contract tests referencing it), cross-phase dependency edges → the **phase DAG artifact**. 3. **Artifacts**: glossary.md + adr/ rendered into the spec dir (render machinery exists); the phase DAG is consumed by L2 parallel lanes.
4. **Shared-understanding gate** (deterministic): spec cannot advance while openQuestions > 0 OR repo-contradiction checks > 0 (mechanically: grill-facts findings not yet waived/dispositioned in the grill artifacts) OR any phase lacks declared ownership+dependency edges (`SpecPhase.owns`/`dependsOn`).
