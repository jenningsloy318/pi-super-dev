Repo under analysis (read-only local clone): `docs/references/deepseek-harness` (github.com/deepseek-ai/deepseek-harness, MIT, developer preview). All paths below are relative to that repo root.

## 1. Overview: the process thesis

DeepSeek Harness is not only an architecture bet ("everything is a plugin", `AGENTS.md:3`); it is a *process* bet: **a codebase developed primarily by AI agents needs its engineering memory, standards, and verification to live in the repository as mechanically-checked artifacts, not in human heads, review threads, or session transcripts.** Every layer observed below serves that thesis:

- Decisions are first-class files with a state machine (Agent Notes, §2).
- Incidents end as named rules, not as closed tickets (postmortems + `docs/defensive-patterns.md`, §3).
- Cross-package runtime contracts are owned by the package that emits the data, and completeness is enforced by a gate (invariants, §4).
- Testing is stratified so a green suite means "the shipped artifact works", with explicit rules for what coverage cannot prove (§5).
- Documentation is a tiered, budgeted, generated-and-verified artifact — including its bilingual half (§6).
- Contributions are selected checks, not reflexive full suites; CI owns exhaustion (§8).

The stance is stated plainly in the root instructions: "Read docs/architecture.md before changing packages/" (`AGENTS.md:5`) and even "We recommend using an agent to explore the codebase and understand its architecture" (`docs/architecture.md:7`) — the docs are written *for agent contributors as the primary reader*.

A deliberate temporal frame: "Pre-release stance: foundation over blast radius … With no external consumers, prefer the correct foundation over compatibility shims: rename or repackage freely and update every reference together. Backends reject old on-disk formats." (`AGENTS.md`, section "Pre-release stance"). `CONTRIBUTING.md` confirms external PRs are not accepted yet and frames the repo as "an idea, an official showcase, and a source of inspiration, but not a mandate" — the community is routed to plugins (`dsh-plugin` topic), not to core patches.

## 2. Agent Notes: a decision-record state machine

### 2.1 Layout and lifecycle

Location `.agents/notes/{lifecycle}/{class}/yyyy-mm-dd-topic-title.md` (`README.md` in that dir). Lifecycle states measured:

| State | Count (EN) | Role |
|---|---|---|
| `implemented/` | 505 (architecture 129, feature 170, process 69, simplification 48, testing 12, bug-fix 77) | Decision shipped; file kept current with reality |
| `proposed/` | 25 | Reviewed-before-build proposals |
| `rejected/` | 11 (10 simplification + 1 feature) | Considered and declined, kept only while the rationale "prevents a tempting, meaningful mistake" |
| `archived/` | 142 | Frozen history, never current authority |

The definition is precise: "An Agent Note records a decision or proposal that affects this codebase — the *why* and *what we gave up*, the parts code and docs can't carry" (`README.md:7`). The rule "Every non-trivial change MUST add or update at least one Agent Note in the same PR; only mechanical/local edits are exempt" appears in *both* the root `AGENTS.md` (Conventions) and `docs/AGENTS.md` (Writing rules), with the scope defined as behavior, contracts, structure, process, formats — "a decision a maintainer may reasonably revisit."

Classes are a closed set enforced by gate: `feature`, `bug-fix`, `simplification`, `architecture`, `process`, `testing`, with a stated discriminator — "architecture is about the source we ship; process is the surrounding tooling and workflow" — and `refactor` deliberately absent because `simplification`'s "does observable behavior change?" already covers it (`README.md`, Classification).

### 2.2 The in-file format (machine-checked)

`pnpm run verify-agent-note-format` (in doc-sync) enforces a three-line header (`# Agent Note: <title>` / blank / `Status: <status>`) where Status must agree with the folder: `proposed`, `implemented`, or `rejected — <why, in one line>`. The rationale is explicit: "The rejection reason is the one status with content, because a rejected Agent Note's verdict is the fact readers come for." Section skeletons are lifecycle-specific: `proposed/` requires `Problem/Proposal/…/Alternatives considered/Acceptance criteria/Risks`; `implemented/` requires `Problem/Decision/…/Alternatives considered/Consequences` and *rejects* proposal-era headings ("`## Proposal`, `## Plan`, `## Migration plan`, and `## Acceptance criteria` may not appear in an implemented Agent Note") because implemented notes "describe shipped reality in present tense". Moving a note between folders re-satisfies the target skeleton mechanically.

**Alternatives considered is mandatory** for every note: "A decision recorded without what it beat invites re-litigation — the failure Agent Notes exist to prevent" (`README.md`). Pre-format notes that cannot reconstruct alternatives carry an exact accepted comment (`<!-- agent-note-format: alternatives-not-recorded (pre-format Agent Note) -->`) — the gate accepts honesty about missing history rather than fabricated content.

### 2.3 Currency and supersession rules

`implemented/AGENTS.md` (13 lines) pins the maintenance duty: "Keep paths, symbols, defaults, and mechanisms current in the same change that alters them. Rewrite stale facts in place; do not append change history," but "This is not a license to rewrite the *decision*" — reversals require a new note with cross-links; consolidation/deletion of a superseded note must preserve "every unique rationale, alternative, consequence, required verification, and named coverage gap," repair inbound links, and delete the Chinese counterpart in the same change. Archived notes are sealed: no edits, translations, moves; `verify-archived-agent-notes.ts` checks "the closed class tree, complete triplets, archive metadata, sidecar hashes, and the append-only frozen-content manifest" (`README.md`, Archiving). There is deliberately **no index file**: the lifecycle tree is the working inventory; the no-index decision itself is a note (`implemented/process/2026-07-19-remove-generated-agent-note-index.md`, linked from `README.md`).

### 2.4 Worked examples read in full

- **Implemented, process — vendoring rescope** (`implemented/process/2026-08-10-vendor-package-rescope.md`): full problem (publishing the harness publishes its framework peer-dependency; upstream names would squat the registry), decision table mapping nine `vendor/` packages to `@deepseek-ai/*`, a precise delimited-token rename rule with *named exemptions* (the `cordis:` builtin prefix, `Symbol.for('schemastery')`, GROUP_ORDER directory names), and four rejected alternatives each with the reason it lost. The rename is script-owned (`scripts/rescope-vendor.ts` with `--apply/--check/--reverse`), the `hygiene` gate runs the residue check every CI pass, and the note even prices the reverse operation ("spans roughly 1300 files, so replay it with the script rather than by hand").
- **Implemented, architecture — invariant service + runtime contracts** (§4 below).
- **Rejected, feature — landstrip for the Windows sandbox rung** (`rejected/feature/2026-07-26-evaluate-landstrip-for-windows-sandbox-rung.md`): Status line carries the verdict *and* the reason: "landstrip is not battle-tested (a days-old single-maintainer project, ~48 GitHub stars at rejection); a security-invariant dependency must have proven adoption." The body preserves the evaluation criteria (probe synthesis, dialect mapping, LGPL license, source/build record) and the outright-rejected alternative (swapping the Linux rung: "the current launcher has reviewable C source and binaries byte-pinned to native CI builds").
- **Rejected, simplification — drop durable step boundaries** (`rejected/simplification/2026-06-20-drop-durable-step-boundaries.md`): rejected because "`step/end` is the durable indication that a model step finished … clearer than inferring completion from adjacent step-scoped events"; the "What we give up" section states exactly which durable fact would be lost.
- **Rejected, simplification — drop bash output spill files** (`rejected/simplification/2026-06-20-drop-bash-output-spill-files.md`): "full-output recovery is a real bash behavior. A future artifact/blob service may generalize it, but dropping spill files before that replacement would lose useful command output" — the rejection defers to a *future replacement*, not to the status quo forever.
- **Proposed — required cancellation through tool-reachable capability seams** (`proposed/architecture/2026-07-19-required-cancellation-through-tool-capability-seams.md`): a full design with a scope boundary (what's in: awaited work the tool still owns; what's out: post-handoff detached work), a migration plan by capability family, and four rejected alternatives (lint enforcement, ToolRunContext threading, ambient async-local signal) each with the failure mode named.
- **Proposed — domain KV storage + workspace entity** (`proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.md`): package tables, dependency directions, backend contract facets — with a cross-link noting which part a later implemented note already superseded.
- **Proposed, process — periodic human-review maintenance for dsh-code-review** (`proposed/process/2026-07-13-human-review-skill-maintenance.md`): an out-of-repo maintenance tool with an acquisition contract (merge-commit reachability as the sole eligibility check, `type: User` actors, strict pre-merge timestamps) — evidence that even *human* feedback ingestion is designed as an evidence-verified pipeline.

## 3. Postmortem culture: incidents → named rules

Four postmortems live in `docs/postmortem/0001..0004`, each with Executive summary / Impact / Timeline / Root cause / Guardrails added / Lessons, each bilingual, each ending in a *rule that generalizes*:

1. **0001 — ACP crashed on real editor connect; 178 green unit tests, 100% line coverage** (`docs/postmortem/0001-acp-default-export-drops-inject.md`). Two stacked bugs: a stray `export default apply` made the Loader's `unwrapExports` discard the namespace plugin's `inject`; and an opportunistic service read (`this.ctx.sessionPersistence`) tripped the inject guard through a traceable *shadow* because the fiber walk is ancestor-only. Every test missed both "for the same reason: every test mounted the plugin through a path that did not exercise how it actually loads or how its services actually resolve." The canonical sentence: "Coverage proves lines *ran*; it says nothing about whether the feature works *the way it ships*." Guardrails: a keyless real-Loader `session/new` e2e ("Verified it fails when `export default apply` is restored" — the guard is proven red-capable), a `TSX_TSCONFIG_PATH` fix so subprocess tests run source not stale builds, and the testing.md "test the real entry path" rule. Lesson includes an epistemics rule: "Trust the trace, not the theory."
2. **0002 — Filesystem tools permanently disabled by an unevaluated `!!js`** (`docs/postmortem/0002-js-expression-disabled-filesystem-tools.md`). `!!js` interpolates only plugin `config`, never entry metadata like `disabled`; the raw expression object was truthy, so fs plugins never mounted — and the snapshot refresh then "proved deterministic replay of the regression rather than successful filesystem behavior" (`UNKNOWN_TOOL` results became expected outputs). Guardrails: `verify-cordis-config` statically rejects expression nodes in Loader entry metadata; `dsh-acp-snapshot` rejects structured `UNKNOWN_TOOL` before it can be committed as a fixture. Lessons: "A snapshot refresh is fixture production, not correctness review," and permission controls must "describe only the capabilities they actually govern."
3. **0003 — Web agent validated a replacement server instead of the current GUI** (`docs/postmortem/0003-web-agent-gui-feedback-loop.md`). An agent-in-the-product incident: the model didn't know which URL/process hosted its session, treated a bare Vite HTTP 200 as success against a white screen, and validated a *replacement* `dsh web` on another port. The evidence source is the persisted session event log, cited by event sequence numbers (30939, 31865, 34309…). Guardrails make runtime identity model-visible (`$DSH_WEB_URL`/`$DSH_WEB_MODE`, an `app:web-surface` prompt section), reject standalone Vite serve during configuration, and add layered real-path tests. Lessons: "HTTP readiness, build success, and a boot manifest are different facts"; "A replacement service cannot prove that an existing page changed"; and a meta-rule about regression tests: "A regression test must be able to fail for the reported mechanism."
4. **0004 — Landlock partial-enforcement notice misclassified child failures** (`docs/postmortem/0004-landlock-partial-notice-misclassified-child-failures.md`). One case-insensitive `landlock-run: ` substring plus any nonzero exit blamed ordinary child outcomes (ripgrep's no-match exit 1) on the sandbox. Root cause is typed as a *representational* failure: "The public sandbox result type could express only a bag of substrings. It could not state that Landlock failure requires exit 125 …" Guardrails: a `RunnerFailureRule` type with per-line fatal signatures and exact informational exclusions, a deterministic POSIX wrapper repro, native-boundary regression specs, and an assembled snapshot composition pinning the product path. The honest scope note: stderr "remains an in-band attribution channel … the tighter conjunction prevents the accidental collision … but does not authenticate the writer."

The bridge from incident to standing law is `docs/defensive-patterns.md` (33 lines): "Hard-won bug-class rules: each pattern below is a class of defect that actually shipped or nearly shipped here, stated as the rule that prevents its recurrence" — orthogonal outcomes reported independently; normalized contracts on both sides of an adapter; async-state ≠ sync-state ("Never treat `agent/status` or `whenIdle()` as the result of one follow-up"); dispose must reach quiescence; contain callback exceptions in the dispatcher; scrub env for spawned commands ("drop `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`"); unlink link-shaped paths. Postmortem README frames the tier: chronology "records evidence, not a teaching sequence" (`docs/AGENTS.md`, tier table).

## 4. Runtime invariants: package-owned contracts + mechanical completeness

Two paired notes define the system:

**The service** (`implemented/architecture/2026-07-19-package-owned-invariant-service.md`): `@deepseek-ai/dsh-invariants` is a "product-independent Cordis service plugin that registers `ctx.invariants`" owning configuration, registration uniqueness, child-fiber lifecycle, and package-attributed failures — "It imports no session, agent, scope, or agent-loop package and contains none of their checks." Every workspace package publishes a `./invariant` companion registering its exact npm name; selection is allow/block regex lists with blocklist precedence; the name reservation survives filtering so "two plugins can never silently claim the same package name"; installer failure rolls back the child fiber atomically; violations throw `InvariantError` with stable `code: 'INVARIANT'` and the owning `packageName`. The invariant-service design is itself documented as a subsystem page (`docs/subsystems/invariants.md`) whose generated Cordis-surface region is byte-verified against source.

**The contracts** (`implemented/architecture/2026-07-19-package-invariant-runtime-contracts.md`): the problem was that the first baseline "accepted empty installers," and a follow-up "replaced those empties with generic assertions about plugin names, injections, effects, service methods" — which "made every companion executable without making the system safer." The decision: a companion either installs a check over "an event stream or relevant mutable data structure," or carries "an owner-specific `No runtime invariant:` comment explaining why the package has no plausible runtime relation to observe. The empty form is an explicit architectural conclusion, not a generated placeholder." At decision time: 21 executable companions, 82 justified empties, with the 21 relationships tabulated (session sequence/turn-step enclosure; agent status transitions; scoped-event subject consistency; loop request reconstruction; LLM stream block grammar; tools' monotonic stages and immutable snapshots; compaction pairing; goal snapshot relationships; jobs/task snapshot relations; time-context agreement with the open turn…).

**The gate**: `verify-package-invariants` "rejects missing companion source, generated markers, unexplained empty installers, non-empty installers that omit or ignore the reporter, foreign or unresolved registration names, missing `./invariant` exports or published files, missing invariant peer/development dependencies and project references, and bundle overrides." Tests execute every companion's `apply` "and verify that it calls `register` with its manifest name, rather than accepting source text alone"; an artifact gate imports the compiled self-reference under plain Node so "a companion that imports an undeclared runtime chunk fails before release." The convention is also in root `AGENTS.md` (Conventions: "Runtime invariants assert owned relationships. Check authoritative event streams or mutable data, not service or method presence…"). Rejected alternatives are recorded for both notes (central checks; implicit root registration; runtime filesystem discovery; validating filters against loaded packages; requiring an assertion from every package).

## 5. Testing philosophy

`docs/testing.md` (tier by tier):

- **Unit** (`pnpm run test`): "Every registry gets an HMR-safety test (dispose the contributing fiber, assert cleanup)" — reload safety is a *unit* concern, not an afterthought; permanent contract-regression tests are cited by example (`packages/core/agent-loop/tests/contract-regressions.spec.ts`).
- **Coverage gate** (`test:coverage`, not `test`): per-file 100% on `packages/*/*/src`, with the stated interpretation: "An uncovered line is often dead code the gate is correctly flagging for deletion, not a missing test to bolt on. Line coverage is necessary, never sufficient — it proves lines ran, not that the feature works as shipped." Platform-honesty example: `pwsh-local` self-skips without a real `pwsh` and is exempted on pwsh-less hosts while "CI runners ship pwsh and enforce the full bar."
- **Real-API e2e**: "We are DeepSeek — do not ration real-API tests… A no-key test proves plumbing; only a with-key run proves the agent works against a real model." Highest value: smoke tests "that boot the real example, send one prompt, and check the world — they catch the 'green unit tests, broken product' class that mocks cannot (postmortem 0001)." Self-skip is explicitly "not a cost signal."
- **Mock policy**: "Mock only the expensive or non-deterministic boundary (LLM adapter, network, clock); keep everything downstream real. A hand-rolled stand-in proves the bridge moves bytes, not that the shipping tool behaves as asserted."
- **Verify the world, not the self-report**: "An e2e assertion re-runs the command or re-reads the file externally; a keyword probe on the agent's own output lets a cheating agent pass. Assert untouched files are byte-identical."
- **Resource ownership**: "e2e tests own their resources: create the harness in the test, dispose in `afterEach` (even on failure/retry/timeout); shared fixtures live in a plain `tests/harness.ts`, never another `*.e2e.ts` (importing a spec re-registers its `describe` and duplicates real API calls)."
- **Real entry path**: product-visible plugins need a REAL-composition test booting test-only `cordis.yml` through the Loader — "Hand-built `ctx.plugin(...)` suites are insufficient"; the default-export regression class gets an explicit rule (`expect('default' in mod).toBe(false)`) with a proof duty: "introduce the regression, watch red, revert." Real entry means the *published* artifact: "a package `bin` runs built `lib/bin.js` under plain `node`, exposing failures tsx masks."
- **Source plane vs artifact plane**: every vitest config resolves workspace imports to `src` via `tsconfig.base.json` paths — "stale artifacts there load a second copy of module singletons"; built artifacts are consumed only by explicitly declared built smokes.
- **Snapshot policy**: "Every non-trivial model-, protocol-, or human-visible change adds or updates a keyless scenario in the same PR through a runnable example's owning snapshot suite. Package tests, e2e assertions, mock/test-only compositions, and PR rationale do not replace the assembled transcript" (restated as a standing convention in root `AGENTS.md`). Record vs refresh are distinct commands; "review every JSONL and expected-output diff."

## 6. Documentation as an engineered artifact

- **Tier taxonomy with "one home per fact"** (`docs/AGENTS.md`): root AGENTS.md = standing orders ("one to three lines each, linking its home"); `architecture.md` = ordered map; `subsystems/` = type definitions + semantics; Agent Notes = why/what-was-given-up; postmortems = "the only tier where war-story narrative belongs"; cookbooks = numbered how-tos; package README = the per-package contract. Placement rules are one line: "bugs → postmortems; rationale → Agent Notes; procedures → cookbooks; type definitions → subsystems."
- **Wordcount budgets** (`verify-doc-budgets`, manifest `scripts/doc-budgets.manifest.json`): root AGENTS.md ≤ 1,600 words; architecture.md ≤ 1,800; docs/AGENTS.md ≤ 1,250. The escalation is ordered: relocate → condense → raise the ceiling with a justified manifest diff. "Ceilings are guardrails, not reduction targets."
- **The slop checklist**: an anti-pattern audit run by the `dsh-doc-standards` skill — duplicated rules ("Grep a distinctive phrase; keep one home and link the rest"), change narration ("previously/now/no longer"), implementation-status annotations ("Status rots"), hand-restated generated catalogs, reasoning transcripts, paragraph walls, emphasis inflation, and "spec-speak in `implemented/` Agent Notes."
- **Verbatim type pastes are gated**: ` ```ts type-equiv ` fences are registered in `scripts/type-equiv.manifest.json` and checked against the symbol's live declaration "via the TypeScript parser" so a paste cannot drift; `doc-typecheck` compiles ordinary `ts` fences (`docs/development.md`, "Documenting types verbatim").
- **Generated + freshness-gated catalogs**: module graph, capability seams, event producer/consumer matrix, tool/config/persistence catalogs (52 `gen-*`/`verify-*` scripts; `pnpm run doc-sync` runs all documentation gates).
- **Prose discipline is a skill**: `dsh-prose-standard` owns "complete-proposition" rules; `dsh-trim-cot-leakage` is a dedicated skill for a distinctly AI-era defect class — "prose whose vantage is the authoring session rather than the repository," with an eight-item taxonomy (dead design-session citations like `(decision 7)`, stack/PR vantage, change narration, review choreography, reviewer-addressed justification, derivation transcripts, hedges, authoring-language slips) and a single test: "could a reader at HEAD, with no access to any session transcript, PR thread, or uncommitted draft, resolve every reference and verify every claim?" Root AGENTS.md encodes its kernel: no metaphors, no narrated control flow, "Before writing `contract`, `boundary`, or `shape`, ask whether a more exact term names the subject."
- **Bilingual pairing as a contract** (`docs/i18n/README.md`): every in-scope doc is a three-file pair (`foo.md`, `foo.zh.md`, `foo.i18n.yaml` recording *git blob hashes* of both sides at last confirmation); "Both languages carry equal authority"; "a PR never lands one language without the other two files." `verify-translation-pairing` checks completeness, hash equality (editing either side without re-confirming goes red), language switchers, and structural signatures (heading depths/order, list kinds and counts, table row/column counts, link targets, verbatim code blocks). A custom Git **merge driver** (`dsh-translation-pairing`, installed via `scripts/install-lefthook.mjs`) composes pairing records during merges and "fails closed on owner conflicts, non-text merge configuration, or invalid records" (`docs/development.md`, Git integrations). The gate's limit is stated honestly: "a green gate means the pair was confirmed consistent at these exact contents, not that the confirmation was sound … A re-recorded pair with a sloppy counterpart passes the gate; it must not pass review."

## 7. Vendoring decision

`vendor/` holds nine pinned upstream packages (Cordis core, cosmokit, schemastery, loader/include/group/timer/hmr/logger-console plugins) republished as `@deepseek-ai/*` because every harness package declares the framework as a **peer dependency** — "publishing the harness publishes this layer with it, and under the upstream names that publication would squat them on the registry" (`implemented/process/2026-08-10-vendor-package-rescope.md`; mapping in `docs/rescope.md`). Discipline: the manifest records upstream SHAs; a lefthook guard checks that `vendor/*/src` edits are staged with the matching manifest update; upstream sync re-applies the rescope via script; `publish-npm-baseline.ts` now "requires every published package to be `@deepseek-ai/*` with no vendored exemption."

## 8. Contribution flow: selected evidence, hooks as checkpoints, CI as owner

- **Pre-push discipline is a skill** (`.agents/skills/dsh-pre-push-checks/SKILL.md`): "select the smallest tests and checks that cover the outgoing or just-published diff without reflexively running the full repository suite." It scripts base-ref verification (`pnpm --silent run change-scope --base <verified-base-ref>` — "The command never guesses or fetches a base") and states the philosophy: "Every behavior change needs the narrowest available test or purpose-built check that would fail for its regression."
- **Root AGENTS.md codifies it**: "Match evidence to the surface: focused tests for behavior, snapshots for model or user output, doc-sync for docs … Never default to the full suite or repeat a passing check for commit or push. CI owns exhaustive coverage and the platform matrix."
- **Hooks are intentionally narrow** (`lefthook.yml`, `docs/development.md`): pre-commit does staged pairing-record verification, archived-note checks, staged oxlint with bounded fix retry, third-party-notices regeneration ("Regenerate rather than reject"), whitespace checks, and the vendor manifest guard; pre-push runs only typecheck. The comment atop `lefthook.yml`: "Keep these local checkpoints fast; CI owns the full repository-wide gate matrix."
- **Sandbox escalation rule for agents** (root `AGENTS.md`, "Host sandbox failures"): when required commands fail because the agent sandbox blocks credentials/network/IPC, "retry unchanged with the narrowest host escalation before diagnosing authentication or project failure. Require sandbox evidence; never bypass genuine test failures or the product sandbox under test."
- **PR mechanics**: choose history deliberately ("fix the introducing PR before propagation"; `--force-with-lease`, never raw `--force`), one `kind/*` plus material `area/*` labels with native Issue Type — each itself an Agent Note (`implemented/process/2026-08-02-native-github-stacks-and-optional-rebases.md`, `…-unified-github-label-taxonomy.md`), plus a `dsh-merging-stacked-prs` skill.

## 10. Design decisions & trade-offs (assessment)

1. **Decision memory as first-class files beats conversation memory — at the cost of volume.** 683 dated notes with mandatory alternatives and lifecycle skeletons make rationale greppable and re-litigation expensive. The cost is real: the tree must be maintained (currency rules, archive sealing, consolidation-with-preservation), and readers must trust that `implemented/` reflects shipped reality — which is why the format gate forbids spec-speak there.
2. **Mechanical completeness beats aspirational coverage.** Invariant companions are exhaustive-by-gate with *explained* empties rather than uniform assertions; generated catalogs are byte-verified; pairing records are hash-pinned. Each gate converts a class of silent drift (undocumented type, stale paste, unsynced translation, missing companion) into a red CI. Trade-off: gate sprawl (52 scripts) and generator maintenance become their own subsystem.
3. **Honest limits are documented, not hidden.** Coverage "proves lines ran"; the pairing gate "cannot judge whether the two sides actually say the same thing"; stderr classification "does not authenticate the writer"; the invariant runtime "does not check the witness" (dsh-02 §5). This honesty is what makes the green signals trustworthy.
4. **Rejected ideas are kept only while useful.** "Keep it only while its rationale prevents a tempting, meaningful mistake; otherwise delete the complete triplet" — a decay policy for negative knowledge, avoiding both amnesia and a graveyard. The 11-vs-505 rejected/implemented ratio shows most refusals happen *inside* implemented notes' "Alternatives considered" sections rather than as standalone files.
5. **Pre-release stance trades compatibility for refactoring speed.** "Foundation over blast radius … Backends reject old on-disk formats" (`AGENTS.md`) — legitimate only while there are no external consumers, and the repo says so with a removal instruction ("Remove this section at the first tagged release").
6. **Checks-selection over full-suite reflex** pushes exhaustion to CI and keeps agent iteration fast — but depends on contributors' selection being honest; the skill therefore anchors selection to "a check that would fail for its regression."
7. **Process weight is proportional to authorship model.** The entire apparatus (notes, gates, budgets, skills, bilingual pairing) is optimized for non-human authors with high throughput and no institutional memory between sessions. A traditional small human team would likely find it heavy; for agent-driven development it is the mechanism that substitutes for water-cooler knowledge.
8. **The AI-era is named, not hidden.** A dedicated skill for chain-of-thought leakage, prose rules against reasoning transcripts, and the "could a reader at HEAD resolve every reference" test acknowledge that the primary author leaves traces a human author wouldn't — and polices them.
