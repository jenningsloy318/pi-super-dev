# Findings — First Methodology Read (2026-09-01)

Careful read of src/control.ts, src/render/render.ts, src/stages/implementation.ts
(phase/attempt loop, RED loop, parallel-review join, gate battery). Each finding names
its escape class. This is the v0.3.53+ backlog, ordered by live cost.

## F1. Post-RED oracle cannot reach the cached runner (D — implicit contract via scoping) — CONFIRMED LIVE, ~1h burned

`redCheckOptions(ctx, phaseId, undefined, setup.defaultBranch)` at the two post-RED
oracle call sites (implementation.ts ~2521/2526) omits the runner parameter that the
RED-loop call site (~1648) passes. Root cause is structural: `runnerSpec` is declared
inside the fresh-RED `else` block, so the post-RED sites CANNOT pass it. With no runner,
the oracle falls back to convention plans; nested project test dirs
(`cosmic-clock-3d/tests/...`) match no convention anchor → zero plans → `unknown` with
NO diagnostic → `tdd-targets-unverified-after-implementation` → no-progress → phase
partial (run 2026-08-31T16-03-57-978Z phases 01/02; the judge independently reproduced
13/13 green). The re-entry only succeeded because by then a phase commit had landed the
tree and the already-satisfied path bypassed the oracle.

Fix: hoist `runnerSpec`/`runnerDiscoveryTried` to attempt (or phase) scope; pass
`runnerSpec ?? undefined` + a diagnostics array at both sites; add the AST parity check
(04-quality §2) + an L3 test (cached runner + nested test dir + green implementer →
phase green, no unverified).

## F2. Join counts checker-failures as suite rejections (E-class enforcement + P5 violation) — CONFIRMED LIVE, ~5h burned

The parallel-review join treats ALL non-STRONG/non-weak outcomes identically: discard
GREEN work, clear acceptedRed, re-author RED, count toward `MAX_PARALLEL_REVIEW_REJECTS`
(3). The live run's reviewer violated source-read-only 8+ times (phases 05/06/07) —
each violation (a CHECKER failure: the reviewer misbehaved) discarded the implementer's
correct work, re-ran tdd-guide (~10 min), and re-launched the same misbehaving reviewer.
Phases 05/06/07 all stopped at the cap → partial → convergence re-entry re-did them.

Fix: classify at the join — contradiction (evidence about the suite) keeps fail-closed
discard; `review?.error` (timeout, boundary violation, spawn failure) becomes fail-open:
keep the work, log `red-review-incomplete (advisory)`, record a ledger finding, count a
SEPARATE `reviewViolations` counter, and after 2 violations disable the parallel review
for the phase (deterministic gates remain authoritative). Keep contradictions on the
existing capped path.

## F3. Abandoned in-flight reviews are orphaned across attempts (C — concurrency) — LATENT, observed indirectly

`redReviewInFlight = null` at attempt start silently drops an unjoined review from a
previous attempt (implementer error/timeout path). The orphaned reviewer keeps running
with a stale boundary snapshot; if it violates, the restore can clobber the NEXT
attempt's writes (the phase-11 "boundary reversion wiped the homepage card" evidence is
this race). Also its dashboard step row stays "running" forever.

Fix: before clearing, await-or-abandon explicitly: `ctx.signal`-abort the child where
supported, else attach a no-op adjudication that logs `review from attempt N abandoned`,
and mark the step row failed/aborted.

## F4. `PROSE_ARRAY_FIELDS` hand map vs schema-driven walk (A/D — asymmetric mechanisms)

String→array coercion (normalizeProseArrays) uses a hand-maintained per-stage map with
7 entries; the reverse direction is schema-driven for every stage. A new/renamed stage
silently misses coercion. Fix: derive coercible array slots from the schema (exact
`type:"array"` of `type:"string"` items, same union guard) and delete the map; keep
`normalizeProseArrays` as a thin wrapper for API stability.

## F5. Contract-drift warnings are invisible in production (P10)

`extractControlKeys` logs drift via `console.warn` — which goes to the extension
process stderr, not run.log/audit. The unbalanced-paren and dropped-fragment warnings
would never be seen in a live run's artifacts. Fix: thread a sink (or emit an event)
so contract drift lands in run.log with the stage/prompt context.

## F6. Extract-order tolerance can accept a NON-control object (P1 edge, accepted risk — document + guard)

If the `<control>` tag body fails to parse AND a later fenced JSON or trailing object
parses, extractControl returns that object — potentially prose example JSON, not the
control. The v0.3.48 repair reduces the frequency but not the possibility. Fix (cheap):
when the tag exists but its body fails AND a fallback object parses, log a loud
`control fallback accepted from <source> after tag-parse failure` line and (if the
fallback lacks ALL declared keys) prefer null over a wrong-object verdict.

## F7. Dashboard step rows for abandoned/retried steps (cosmetic, P10)

`runStep` rows are emitted ok/failed at resolution; abandoned promises keep "running"
forever (see F3). Fix pairs with F3.
