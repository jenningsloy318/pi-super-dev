# Findings — First Methodology Read (2026-09-01)

Careful read of src/control.ts, src/render/render.ts, src/stages/implementation.ts
(phase/attempt loop, RED loop, parallel-review join, gate battery). Each finding names
its escape class. This is the v0.3.53+ backlog, ordered by live cost.

## F1. Post-RED oracle cannot reach the cached runner (D — implicit contract via scoping) — CONFIRMED LIVE, ~1h burned

`redCheckOptions(ctx, phaseId, undefined, setup.defaultBranch)` at the two post-RED
oracle call sites (implementation.ts ~2521/2526) omits the runner parameter that the
RED-loop call site (~1648) passes. Root cause is structural: `runnerSpec` is declared
inside the fresh-RED `else` block, so the post-RED sites CANNOT pass it. With no runner,
the oracle falls back to convention plans; nested project test dirs
(`cosmic-clock-3d/tests/...`) match no convention anchor → zero plans → `unknown` with
NO diagnostic → `tdd-targets-unverified-after-implementation` → no-progress → phase
partial (run 2026-08-31T16-03-57-978Z phases 01/02; the judge independently reproduced
13/13 green). The re-entry only succeeded because by then a phase commit had landed the
tree and the already-satisfied path bypassed the oracle.

Fix: hoist `runnerSpec`/`runnerDiscoveryTried` to attempt (or phase) scope; pass
`runnerSpec ?? undefined` + a diagnostics array at both sites; add the AST parity check
(04-quality §2) + an L3 test (cached runner + nested test dir + green implementer →
phase green, no unverified).

## F2. Join counts checker-failures as suite rejections (E-class enforcement + P5 violation) — CONFIRMED LIVE, ~5h burned

The parallel-review join treats ALL non-STRONG/non-weak outcomes identically: discard
GREEN work, clear acceptedRed, re-author RED, count toward `MAX_PARALLEL_REVIEW_REJECTS`
(3). The live run's reviewer violated source-read-only 8+ times (phases 05/06/07) —
each violation (a CHECKER failure: the reviewer misbehaved) discarded the implementer's
correct work, re-ran tdd-guide (~10 min), and re-launched the same misbehaving reviewer.
Phases 05/06/07 all stopped at the cap → partial → convergence re-entry re-did them.

Fix: classify at the join — contradiction (evidence about the suite) keeps fail-closed
discard; `review?.error` (timeout, boundary violation, spawn failure) becomes fail-open:
keep the work, log `red-review-incomplete (advisory)`, record a ledger finding, count a
SEPARATE `reviewViolations` counter, and after 2 violations disable the parallel review
for the phase (deterministic gates remain authoritative). Keep contradictions on the
existing capped path.

## F3. Abandoned in-flight reviews are orphaned across attempts (C — concurrency) — RESOLVED v0.3.54 (see F3-real below)

`redReviewInFlight = null` at attempt start silently drops an unjoined review from a
previous attempt (implementer error/timeout path). The orphaned reviewer keeps running
with a stale boundary snapshot; if it violates, the restore can clobber the NEXT
attempt's writes (the phase-11 "boundary reversion wiped the homepage card" evidence is
this race). Also its dashboard step row stays "running" forever.

Fix: before clearing, await-or-abandon explicitly: `ctx.signal`-abort the child where
supported, else attach a no-op adjudication that logs `review from attempt N abandoned`,
and mark the step row failed/aborted.

## F4. `PROSE_ARRAY_FIELDS` hand map vs schema-driven walk (A/D — asymmetric mechanisms) — FIXED v0.3.54

String→array coercion (normalizeProseArrays) uses a hand-maintained per-stage map with
7 entries; the reverse direction is schema-driven for every stage. A new/renamed stage
silently misses coercion. Fix: derive coercible array slots from the schema (exact
`type:"array"` of `type:"string"` items, same union guard) and delete the map; keep
`normalizeProseArrays` as a thin wrapper for API stability.

## F5. Contract-drift warnings are invisible in production (P10) — FIXED v0.3.54

`extractControlKeys` logs drift via `console.warn` — which goes to the extension
process stderr, not run.log/audit. The unbalanced-paren and dropped-fragment warnings
would never be seen in a live run's artifacts. Fix: thread a sink (or emit an event)
so contract drift lands in run.log with the stage/prompt context.

## F6. Extract-order tolerance can accept a NON-control object (P1 edge, accepted risk — document + guard) — FIXED v0.3.54

If the `<control>` tag body fails to parse AND a later fenced JSON or trailing object
parses, extractControl returns that object — potentially prose example JSON, not the
control. The v0.3.48 repair reduces the frequency but not the possibility. Fix (cheap):
when the tag exists but its body fails AND a fallback object parses, log a loud
`control fallback accepted from <source> after tag-parse failure` line and (if the
fallback lacks ALL declared keys) prefer null over a wrong-object verdict.

## F7. Dashboard step rows for abandoned/retried steps (cosmetic, P10) — VERIFIED ALREADY-RESOLVED by v0.3.51

`runStep` rows are emitted ok/failed at resolution; abandoned promises keep "running"
forever (see F3). Fix pairs with F3.

## v0.3.54 resolution record (same-day application of the methodology)

- **F1/F2** — fixed in v0.3.53 (runner hoist + AST parity test; fail-open join with
  violation counter and phase-level disable).
- **F3-real (the LIVE half of F3)** — the attempt-start orphan is provably dead (TS
  narrows the reset to `never`: the join always nulls first). The REAL race is the
  boundary guard's blind `git restore` during a LIVE concurrent review: clean-at-start
  file + reviewer violation → restore to HEAD → implementer's concurrent legit writes
  destroyed (phase-11 "boundary reversion wiped the homepage cosmic card"). Fix: calls
  flagged `concurrentWriter: true` QUARANTINE violating bytes to a tmp dir and throw
  WITHOUT restoring; the join site then attributes each path — unclaimed paths (only
  the reviewer touched them) are git-restored safely, implementer-claimed/test paths
  stay in place with the quarantine copy preserved and the F2 ledger finding naming
  them. Research validated the shape (validate-after-repair; approval-gate over blind
  enforcement).
- **F4** — `proseArrayPairsFromSchema` derives (container, field) pairs from the stage
  schema (exact `array` of exact-string-`items`, unions excluded); the hand map is
  gone; bdd `traceability[].scenarios` (never in the old map) now covered, pinned by
  test.
- **F5** — `noteControlDrift` ring buffer + `drainControlDrift()`; workflow drains it
  into the run log with the call id right after computing controlKeys.
- **F6** — `extractControl(text, expectedKeys?)`: after a tag-parse failure a fallback
  object is accepted only when it carries at least one declared key (validate-after-
  repair per jsonrepair/outputguard research); wrong-object rejections and legacy
  acceptances are both loud telemetry via F5.
- **Near-miss (render finding)** — missing-required errors append
  `(near miss: the object has "sumary" — did you mean "summary"?)` via a
  Levenshtein-≤1 check against present keys (typebox@1.1.38 message shape
  ground-truthed: unquoted, comma-separated).
- **F7** — verified already-resolved: `runStep` emits the row `failed` in its own
  catch before rethrowing, and the v0.3.51 `void .catch()` keeps the rejection
  handled; no row can stay "running" after settlement.
- **F6 wiring gap (self-caught post-implementation)** — the `expectedKeys`
  guard existed but NO production call site passed it (test-only guard). All
  six production `extractControl` sites now thread the stage's declared keys
  (delegation ×2 via `opts.controlKeys`, session backend via `keys`,
  resume-recovery via `call.controlKeys`, subprocess `runPi` via new
  `expectedKeys` param, RPC path via `RpcRunOptions.controlKeys` → all five
  `resolveTurnControl` sites). A class-E source-contract invariant test fails
  the suite if any future production call site drops the second argument.

## Multi-angle review of v0.3.53–0.3.54 (2026-09-01, post-implementation)

Three reviewer angles ran on the cumulative diff (correctness + adversarial
completed; security died twice on provider 429s — relaunched post-release,
findings become v0.3.55 if real). Both completed reviews returned
"findings-require-changes"; triage:

- **F-A (MAJOR, both reviewers, same seam)** — `attributQuarantinedViolations`
  compared RAW implementer claims against guard-normalized violation paths, so
  a `./x`/backslash-styled claim lost attribution and the restore wiped the
  implementer's own concurrent edit to a file it HAD claimed. Worse, this runs
  in the v0.3.53 fail-open branch where NO retry follows and the change gate
  snapshots the tree AFTER the restore — the under-claim was laundered. The
  old trust-bound comment ("the change gate fails the attempt, a retry is
  coming") was factually wrong for this branch. Fixes: (1) one normalizer on
  both sides (`\`→`/`, strip `./`, trim); (2) restore only when the control
  declared ≥1 file — a null/all-empty control carries no attribution signal
  and now restores NOTHING; (3) comment rewritten to state the honest residual
  risk (an omitted path can still be restored; bytes survive in the quarantine
  dir; the F2 finding names every path).
- **F-B (P2, both)** — producer text format broke on filenames containing
  `", "` (mis-split fragments could collaterally git-restore a coincidental
  modified file) and on quarantine dirs containing a space (Windows tmpdir;
  `\S+` capture lost, evidence pointer dropped). Producer now JSON-encodes
  paths+dir (`formatBoundaryQuarantineError`, workflow.ts, single source —
  the regression tests build fixtures through it so the producer↔parser
  coupling is pinned); consumer JSON-parses with the legacy comma text kept
  as fallback.
- **F-C (P2, code)** — the fail-open join keyed on `review.error` alone; a
  control parsed WITH an off-enum verdict (e.g. "REJECTED" via an
  unconstrained `<control>` path) plus a backend error was dropped on the
  floor (laundered into a keep). Join now fails open only when NO verdict text
  was parsed; any parsed verdict is suite evidence and stays fail-closed.
- **F-D (P2, adversarial)** — capture-side F6 drift telemetry drained only at
  prompt-assembly time, so result-time emissions landed under the NEXT call's
  id or never. `drainControlDrift()` now also runs at result time (success +
  throw paths) under the same call id.
- **F-E (P2, both)** — `nearMissHint` scanned the ROOT control for every
  missing-required error, so the hint was dead for nested slots — including
  its motivating `findings[].evidence` class. It now resolves the errored
  object(s) along `err.schemaPath` (`properties` descends, `items` fans out
  over elements; deeper segments describe the element schema and stop
  instance resolution).
- **F-F (nits, fixed)** — item-level `enum` on string arrays excluded from
  prose-array derivation (a wrap would trade a located error for a worse
  enum-check failure); stale "HOISTED to attempt scope" comment corrected to
  the actual phase scope (a real once-per-phase discovery budget).
- **Watch-items (no code change, documented)** — module-global drift buffer
  can misattribute telemetry lines across concurrent calls (log noise only);
  schema-derived prose coercion now also covers semantic file-list fields
  (forbiddenFiles/ambiguousFiles — inert consumers today, revisit if a gate
  ever reads them); reviewer-created untracked files can't be restored and
  fall to the change gate (conservative, noted in the doc comment).

Result: 10 new regression tests (producer-coupled quarantine fixtures,
comma-path, space-dir, legacy fallback, `./`-claim, null/empty-claims,
nested near-miss, items.enum, off-enum-verdict fail-closed ×2). Suite
211 files / 3125 passed / 3 skipped; coverage 92.55/80.29/94.87.

## Delegation ambient-capability audit (2026-09-02, user question) — skills gap FIXED v0.3.59

Question: do pi-subagents children benefit from installed extensions, and do they
load skills on keyword match?

Evidence (machinery probes + live child transcripts):

| Capability | Session backend | Subprocess backend | pi-subagents delegation |
|---|---|---|---|
| Skills (lazy, keyword-matched) | ✓ host session | ✓ since v0.2.10 W4 (`skillsEnabled()`) | ✗ → **✓ v0.3.59** (`inheritSkills: skillsEnabled()`; was pi-subagents default FALSE → `--no-skills`) |
| Ambient extensions (global `~/.pi/agent/extensions`) | ✓ host session | ✗ (`--no-extensions`, deliberate isolation) | ✓ load (registration `extensions` undefined → `disableAmbientExtensions=false`; probed via `resolvePiLaunchToolPlan`) |
| Extension-registered TOOLS | ✓ | ✗ | inactive — super-dev's explicit `--tools` allowlist filters ALL tools incl. extension tools (pi agent-session `_refreshToolRegistry`); event handlers still run |
| Why not visible in run.log | — | — | child-side activation never propagates; v0.3.59 adds `skills=on/off` to the registration line |

Design notes:
- Ambient extensions must stay loadable in delegation children: pi-subagents
  resolves child model providers through ambient extensions; `extensions: []`
  would break launches. Their tool surface is already allowlist-controlled.
- Skills stay advisory context (P4): the tool allowlist remains the mechanical
  boundary; a child reading an inapplicable skill wastes tokens, nothing more.
- Residual asymmetry (deliberate, documented): subprocess children are
  extension-isolated; delegation children are not — required for provider
  resolution. SUPER_DEV_NO_SKILLS=1 is the only skills kill switch, all backends.
